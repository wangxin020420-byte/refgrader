# 下一阶段执行清单

目标：验证预算约束下三支决策能否降低自动结案风险、合理分配仲裁和人工资源。QWK与MAE继续报告，不预设方法必然有效。

| 顺序 | 工作 | 验收条件 |
|---|---|---|
| 0 | 冻结PC1与PC2 | 两个独立目录、SHA清单、逐份分数与检查点一致；PC2未导出前不标记两臂已全部核验 |
| 1 | 对齐两臂 | 相同测试ID、教师分、满分、审核政策、划分和模型合同；分别记录拟合参数 |
| 2 | 建立统一评价 | 区分BND调用与最终转人工；使用最终机器分评价自动结案风险；固定2分与题目相关容差分开 |
| 3 | 验证集离线诊断 | 按题目交叉验证，比较等权、分歧及学习风险；不根据测试集选择阈值 |
| 4 | 小步修改 | 先成本与状态，再阈值可达性，再动作门禁；分别测试，不修改原run或原指纹 |
| 5 | 补必要仲裁 | 只补缺失候选与证据；不能把未调用的反事实当成无收益；新智谱调用前离线核对Coding Plan URL |
| 6 | 冻结确认协议 | 主指标、资源预算、两支/随机对照及金标版本预先确定 |
| 7 | 确认与写作 | 独立数据、配对统计、题目相关性、实际教师复核耗时；报告无可行策略等负结果 |

当前审核继续在原工作区进行；其新增决定不激活到旧85条基线。数据版本变化和方法变化分别记录。
若在既定预算下无法满足安全约束，先分析原因，不通过修改容差或强行增加NEG比例宣称成功。

现有诊断脚本：`scripts/diagnose_bidirectional_credit_risk.py`、`scripts/diagnose_regularized_bidirectional_risk.py`。
它们是风险识别诊断，不等于完整三动作策略；当前不因完成目录整理而启动新的全量实验。
